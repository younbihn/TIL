## VM 부팅 중 grub: out of memory (원인은 UTM Memory 값이 0)

**상태**: 해결. 메모리를 1536 으로 고쳐 시작해 정상 부팅. 어느 VM 이었는지는 기록하지 않았다 (미확인).

**증상**
UTM 에서 VM 네 대를 한꺼번에 시작하자 한 VM 이 부팅하지 못했다.
error: ../../grub-core/loader/arm64/linux.c:298:out of memory.
Press any key to continue...
- 키를 누르면 GRUB 메뉴로 돌아가고, 항목을 골라도 같은 오류가 반복됐다
- 메뉴 항목: 5.14.0-687.66.1(최신), 5.14.0-687.10.1(이전), rescue. **세 항목 모두 같은 오류**

**원인**
UTM VM 설정의 **System → Memory 값이 0** 이었다. 부트로더가 커널과 initramfs 를 올릴 메모리를 확보하지 못했다.

**진단 과정 (틀린 가설 포함)**
1. 처음에는 새로 설치된(패치로 들어온) 커널이 원인일 것으로 추정했다 → **세 항목이 모두 실패해서 기각**. 특정 커널의 문제가 아니었다
2. 맥 전체의 메모리 부족을 의심해 활동 상태 보기를 확인했다: 메모리 압력 초록, 스왑 0바이트, 사용 11.46GB/16GB → 맥 쪽은 여유가 있어 기각
3. VM 설정의 Memory 를 열어 보니 0

**해결**
VM 을 끈 상태에서 Memory 를 `1536`(MiB)로 입력해 저장하고 다시 시작. 나머지 VM 의 값도 확인했다 (lab 1536, app·db 2048).
- UTM 의 메모리 값은 **MiB 정수**로 입력한다. 메모리는 VM 이 꺼져 있을 때만 바꿀 수 있다

**참조**
- GRUB 의 arm64 리눅스 로더 오류 문구, UTM 설정 System → Memory

**교훈**
- 증상(부트로더 단계의 out of memory)이 원인(설정값 0)을 전혀 가리키지 않아서 반나절을 쓰기 쉬운 유형이다. 부팅 단계에서 `out of memory` 가 나면 커널을 의심하기 전에 **VM 에 할당된 메모리 값부터** 본다
- "모든 선택지에서 같은 오류"는 선택지가 아니라 그 앞단(환경)이 원인이라는 신호다
- 호스트 쪽 여유는 메모리 압력 그래프(색), 스왑 사용량, 압축된 메모리로 판단한다
- 여러 VM 을 켤 때는 한 대씩 로그인 프롬프트가 뜰 때까지 기다리며 켠다
