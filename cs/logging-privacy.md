# 로깅과 개인정보

## 로그에 남기면 안 되는 것
- 비밀번호는 평문이든 해시든 금지 → 로그 유출 시 오프라인 대입 공격 가능(bcrypt는 시간만 벌어줌)
- 로그는 확산성이 큼: 서버 파일 → 로그 수집 서비스 → 백업 → 다수 열람 권한
  → DB는 애써 지키는데 로그가 허술하면 취약 지점이 그쪽으로 이동
- 원칙: 로그에는 "값"이 아니라 "사건"을 남긴다

## 개인정보 마스킹
- 이메일: 앞 2글자만 노출 (younbihn@x.com → yo******@x.com)
- IP는 계정과 결합 시 개인정보로 취급 → 목적 명시·보관기간(통상 3~6개월)·접근통제·방침 고지 필요
- IP 마스킹은 트레이드오프: 프라이버시 ↑ vs 어뷰징 탐지 정밀도 ↓
  (선택지: 전체 저장 + 접근통제 강화 / 마스킹 / salt 해싱 후 동일성만 비교)

## logging 모듈
- print 대신 logging 사용: 레벨 구분(debug/info/warning/error), 시각 자동 기록, 출력 위치 제어
- logger.info("msg: %s", value) 형태 권장 → 출력 안 될 로그는 문자열 조립 자체를 건너뜀
- 시각은 basicConfig의 format에 %(asctime)s 넣으면 자동

## 주의
- FastAPI에서 클라이언트 IP는 Request 객체로 접근: request.client.host
- 프록시/로드밸런서 뒤에서는 프록시 IP가 찍힘 → X-Forwarded-For 필요(단 위조 가능, 신뢰 프록시 전제)
